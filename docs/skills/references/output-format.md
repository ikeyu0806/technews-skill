# ダイジェストの出力

ユーザーの希望する分量・形式を優先する。既定は日本語の短い導入と、各2〜4文の番号付きリスト。日付、話題性の根拠、元記事と議論への直接リンクを入れる。見出しや表は、比較・分類に役立つときだけ使う。

## 導入

調査基準日、対象期間、反応数の確認時点を短く伝える。例:

> YYYY年MM月DD日時点で、直近1週間を中心に国内外から10件を選びました。反応数は同日時点の確認値です。実務への示唆は、記事を踏まえた私の整理です。

これらの数字や日付は実際の調査に合わせる。この記事の例をそのまま埋めない。

## 1項目の形

```text
1. **〈何が面白いか伝わるタイトル〉（〈分野〉／〈記事公開日〉）**
   〈何が起きたか、どのような主張・実験なのか〉。
   〈読みどころ、制作・開発・利用への接点。考察ならそう分かる表現〉。
   〈話題性: HNのNポイント・Mコメント、専門媒体のTrending掲載など〉。
   [元記事](実際に確認したURL)・[一次資料](実際に確認したURL)・[議論](実際に確認したURL)
```

同じ内容のリンクを増やす必要はない。元記事が一次資料なら、元記事と議論の2つでよい。コミュニティの反応を紹介した場合は、その記事の議論ページへリンクする。

## 話題性の書き方

| 確認したもの | 表現例 |
| --- | --- |
| 記事単位の実際の投票数・コメント数 | 「HNでNポイント・Mコメント」 |
| はてなの記事別ページ | 「はてなNブクマ」 |
| 実際に確認したTrending欄 | 「80 LevelのTrending欄に掲載」 |
| 専門媒体による取材 | 「専門媒体の取材記事として選定」 |
| 反応の数字を取得できない新しい研究・デモ | 「新しい試みとして選定。反応数は未確認」 |
| 以前の記事が現在の人気欄にある | 「公開はMM月DD日。今回、HNの人気欄に再浮上」 |

「世界中で話題」「爆発的に人気」のような強い表現には相応の裏付けが必要。根拠が掲載だけなら掲載と書く。

## 人物・研究・ハードウェアの補足

- 人物発信: 発言者、発言日、どの場で何について述べたかを示す。匿名関係者による報道を本人の発言として扱わない。
- 研究・デモ: 何を示したかと、研究段階・限定された条件・一般利用可否を短く示す。未公開のコードや重みを公開済みとしない。
- ハードウェア: 実機レビュー、メーカー発表、認証書類、リークを明記する。公称性能を測定結果と混同しない。
- リリース: 公開日と正式版・プレビューなどの状態を示す。改善率の対象や移行の必要性を確かめ、告知文だけで一覧を埋めない。
- イベント: 依頼に含まれる場合、発表済みの内容と開催予定を分ける。予定日を過去の出来事として扱わない。

## 情報源の発見を頼まれた場合

今回確認した候補を小さな表で紹介する。

| 情報源 | どの分野を拾えるか | 採用理由 |
| --- | --- | --- |
| 確認したサイトへのリンク | 技術記事、3D制作、XRなど | 実際に見つけた記事・議論、元資料への辿りやすさ |

ニュース本文の要約と、収集サイトの評価を区別する。読めなかったサイトについて、確認したような紹介を書かない。

## 提出前の確認

- 数字・日付・引用・リンクは取得した資料と一致しているか。
- 記事の更新日や人気欄の掲載時刻を公開日と取り違えていないか。
- 発言、報道、提供元の評価、自分の考察が区別されているか。
- ベンチマークの一部を全体の性能として説明していないか。
- 同じ話題を複数の項目で数えていないか。
- 広い依頼では、海外の記事とユーザーの複数の関心を探索したか。
- 公式リリースだけに偏らず、実録・議論・人物・作品・新しい試みを拾ったか。
- 未確認の内容を数合わせで入れていないか。
